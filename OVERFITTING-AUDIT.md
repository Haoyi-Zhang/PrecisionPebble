# Finite-Evidence and Overfitting Audit

This project does not train a statistical model, fit parameters, or select a policy from a train/test split. “Overfitting” therefore means a narrower implementation risk: code tailored to frozen case names, retained outputs, or one generator path rather than the declared semantics.

## Controls actually present

- Small complete configuration searches use a state space different from the preparation-aware recurrence. There are 286 completed searches and 283 comparisons to which the contractive theorem applies.
- Bellman certificates are checked by fresh recursive recomputation, not by trusting the optimizer's stored dependency order.
- Event witnesses are replayed from actions, and the claimed-cost entry point must agree with both trace and certificate recomputation.
- The 89/91 result is also checked by a separately implemented fixed-state move-rule path and a literal complete-child recurrence evaluator.
- Ten destructive/invalid controls alter states, capacity, root storage, claimed optimum, certificate costs or keys, theorem applicability, enumeration limits, and reference-policy input conditions.
- Strict parsing tests reject fractional and Boolean values in integer fields, while preserving exact legal rationals.
- Recovery and comparison fixtures reject missing campaigns, common omissions, stale input digests, same-count identity substitutions, and over-budget completion.

No code path is documented as a statistical holdout study, and no natural-workload generalization is inferred. The 364 records are deterministic coverage/regression cases. The 54 exact-integer kernels are constructed instances. Preparation improves none of those 54 cases over typed contiguity; this retained negative result prevents the designed separation family from being presented as evidence of prevalence.

## Residual risk

The optimizer, oracle, and checkers share the written model, so a common specification error remains possible. The finite checks reduce implementation-specific risk but do not supply independent peer review, mechanized proof, production-workload coverage, or cross-platform equivalence.
